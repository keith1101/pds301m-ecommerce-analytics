# Dataset Storage and Reproducibility

The UCI Online Retail dataset and regenerated CSV files are not committed to Git.

Store the original dataset locally at:

`data/raw/online_retail.xlsx`

Processed outputs are generated by the current pipeline.

## Dataset Files

- `data/raw/online_retail.xlsx`: Original UCI Online Retail dataset.
- `data/raw/tiki/raw_tiki_products.csv`: Harvested raw Tiki product listings (category 8322, 1815, 1882).
- `data/raw/tiki/raw_tiki_reviews.csv`: Harvested raw customer purchase reviews.
- `data/processed/cleaned_retail.csv`: Valid non-cancelled sales transactions.
- `data/processed/cancelled_retail.csv`: Cancelled transactions whose `InvoiceNo` starts with `C`.
- `data/processed/anomaly_orders.csv`: Orders flagged as Revenue anomaly, Quantity anomaly, or both.

## Cleaned Dataset Contract

| Column | Rule |
|---|---|
| `InvoiceNo` | Nullable string validation is applied before filtering. Missing, blank, `NaN`, `None`, and `<NA>` values are rejected. |
| `StockCode` | Product code from the source dataset. |
| `Description` | Missing values are replaced with `Unknown`. |
| `Quantity` | Converted to numeric and must be greater than zero for valid sales. |
| `InvoiceDate` | Converted with `pd.to_datetime`; invalid values are removed. |
| `UnitPrice` | Converted to numeric and must be greater than zero for valid sales. |
| `CustomerID` | Missing values can be represented as `Guest` for non-RFM analysis. |
| `Country` | Country from the source dataset. |
| `Revenue` | `Quantity * UnitPrice`. |
| `YearMonth` | Month extracted from `InvoiceDate` in `YYYY-MM` format. |

## Duplicate Policy

Duplicate detection uses exact duplicated rows after basic type conversion and normalization.

When:

```python
deduplicate=True
```

duplicate rows after the first occurrence are removed.

The audit records:

- duplicate row count;
- Quantity difference caused by deduplication;
- Revenue difference caused by deduplication.

When:

```python
deduplicate=False
```

duplicates are retained and the Quantity/Revenue deduplication impact is zero.

Duplicate detection does not assume that two rows with the same `InvoiceNo` are duplicates. An invoice can legitimately contain multiple product lines.

## Anomaly Policy

Order-level anomaly detection uses upper-tail IQR:

```text
Upper Bound = Q3 + 1.5 * IQR
```

Two anomaly flags are calculated:

```text
IsRevenueAnomaly
IsQuantityAnomaly
```

The combined anomaly flag is:

```text
IsAnomaly =
IsRevenueAnomaly OR IsQuantityAnomaly
```

`anomaly_orders.csv` contains all orders where:

```text
IsAnomaly = True
```

Business-impact reporting is separated into:

- Revenue anomaly;
- Quantity anomaly;
- Combined anomaly.

An anomaly is a review flag and is not automatically removed from the dataset.

## Local Workflow

Run all commands from the repository root.

### 1. Install dependencies

```bash
python -m pip install -r requirements.txt
```

### 2. Place the raw dataset

Place:

```text
online_retail.xlsx
```

at:

```text
data/raw/online_retail.xlsx
```

### 3. Run tests

```bash
python -m pytest -q
```

### 4. Regenerate processed outputs

Delete previous generated files if they already exist:

```text
data/processed/cleaned_retail.csv
data/processed/cancelled_retail.csv
data/processed/anomaly_orders.csv
charts/revenue_boxplot.png
```

Then run:

```bash
python src/main.py
```

## Generated Outputs

The pipeline generates:

```text
data/processed/cleaned_retail.csv
data/processed/cancelled_retail.csv
data/processed/anomaly_orders.csv
charts/revenue_boxplot.png
```

Processed CSV files are excluded from Git.

Analysis charts under `charts/` are tracked in Git so that review and report artifacts are reproducible and visible in pull requests.

## Verification

Run:

```bash
python -m pytest -q
```

The complete test suite must pass before opening the pull request.

The generated `anomaly_orders.csv` must satisfy:

```text
IsAnomaly =
IsRevenueAnomaly OR IsQuantityAnomaly
```

The chart must be regenerated from the latest source code before the pull request is submitted.

## Tiki Raw Dataset Contract (Secondary Data Source)

The Tiki dataset is harvested via public API endpoints and serves as an independent secondary validation dataset. In compliance with the project data contract, it is never joined directly into UCI Online Retail tables.

### 1. Raw Files Location

- `data/raw/tiki/raw_tiki_products.csv`: Consolidated product catalogue across targeted categories.
- `data/raw/tiki/raw_tiki_reviews.csv`: Consolidated customer purchase reviews.
- `data/raw/tiki/all_products.json` & `data/raw/tiki/all_reviews.json`: Optional unflattened JSON raw payload cache.

### 2. Raw Products Schema (`raw_tiki_products.csv`)

| Column | Type | Description & Nullability Rule |
|---|---|---|
| `id` | `int` | Unique Tiki product ID (Primary Key). Non-null. |
| `sku` | `str` | Product SKU code. Can be empty string or null. |
| `name` | `str` | Full product title/description. Non-null. |
| `price` | `float` | Current selling price in VNĐ. Numeric > 0. |
| `original_price` | `float` | Original list price before discount. |
| `discount` | `float` | Discount amount in VNĐ. |
| `discount_rate` | `float` | Percentage discount rate (0 to 100). |
| `rating_average` | `float` | Average customer star rating (0.0 to 5.0). |
| `review_count` | `int` | Total number of customer reviews for product. |
| `seller_id` | `int/str` | Identifier of the merchant / vendor. |
| `seller_name` | `str` | Name of the selling store or Official Tiki Trading. |
| `primary_category_name` | `str` | Primary category title (e.g., Nhà Sách Tiki, Thiết Bị Số). |
| `quantity_sold` | `int` | Total units sold (extracted from summary). |
| `quantity_sold_text` | `str` | Raw string representation (e.g., 'Đã bán 1.2k'). |

### 3. Raw Reviews Schema (`raw_tiki_reviews.csv`)

| Column | Type | Description & Mapping Rule |
|---|---|---|
| `id` | `int` | Unique review ID. Used as basis for `InvoiceNo` (`TIKI_REV_{id}`). Non-null. |
| `product_id` | `int` | Foreign Key referencing `raw_tiki_products.id`. Non-null. |
| `customer_id` | `int/str` | Customer user ID. Maps to `CustomerID`; empty/null maps to `'Guest'`. |
| `customer_name` | `str` | Customer display name. |
| `purchased` | `bool` | True if verified purchaser badge is confirmed. |
| `purchased_at` | `int/float` | Unix timestamp (seconds) when purchase occurred. |
| `rating` | `int` | Star rating awarded by customer (1 to 5). |
| `created_at` | `int` | Unix timestamp (seconds) when review was submitted. Maps to `InvoiceDate`. |
| `title` | `str` | Review heading/title. |
| `content` | `str` | Review body feedback text. |

### 4. Harvesting Pipeline Reproduction

To reproduce or refresh the Tiki raw dataset without CLI arguments:

```bash
python src/tiki_scraper.py
```

The pipeline uses circuit breaker resilience, connection pooling, and disk-level caching in `data/raw/tiki/` to prevent redundant network invocations. Raw files under `data/raw/` are excluded from Git version control.
